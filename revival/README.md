## 可重复执行

使用Python 3.12或更新版本；仅依赖标准库。在游戏根目录执行：

```text
python revival/inspect_client.py --verify-all
python revival/verify_resources.py
python revival/recover_world.py
python revival/recover_ui.py
```

上述资源工具只读取原客户端，所有生成文件写入`revival/`；首次基线会保留，后续运行先核对已有原始文件。

用户随后要求优先建角进游戏，新增`prepare_client.py`完整复制客户端至`runtime/client`，只在副本内将选服地址设为127.0.0.1:28993。`client_compat.py`在原文件哈希与指令匹配后生成CPUID兼容候选，并在副本内把启动清单改为普通权限。原始安装目录的文件保持不变。先运行`serve.py`，再用`启动客户端.cmd`打开客户端；后者通过`launch_client.py`启动自己的新进程，在原指令匹配后修正RGBA纹理的Direct3D格式，解决红蓝通道互换。此修正只作用于所启动副本的内存，不改磁盘文件。

早期`gateway_probe.py`首包采集器已停止；现在由`serve.py`监听127.0.0.1:28993。`runtime/accounts.sqlite3`保存测试账号及角色，`runtime/gateway.jsonl`记录连接和消息类型，不记录密码、摘要或认证正文。原始流保存在本地`evidence/gateway-probe`，不应作为公开调试日志上传。

`serve.py`目前实现Challenge/Response、密钥交换、持续RC4流、下行MPPC、角色列表、建角持久化、重名拒绝、选角预检、世界初始数据、游戏时间与场景通知。姓名按客户端提示限制为2至8个字母/汉字，拒绝非法字符及纯数字；最多3角是本地复原策略。形象使用原建角配置中的color1/color2/color3模型ID，不能用配置行号替代。

世界交接按原生协议顺序发送SEnterWorld、SGameTime、SRoleEnterScene；客户端回发CAfterEnterWorld已实际收到。缺少SGameTime会使活动管理器未创建并在进图时崩溃，此前故障已复现并修正。当前临安位置来自原太湖入口传送配置（530,436），HP/MP=100属于本地实验初值，不是已恢复的原版出生点或属性公式。

本次显示曾先全黑、后正常出现地图及人物；期间没有再改服务端或客户端。黑屏恢复原因尚未确认，不能把它写成已定位并修复的渲染故障。用户最终截图和运行记录见`evidence/world-entry-acceptance.json`及`PROGRESS.md`第四批。

实际游戏调用的网络版本是601（0x259），由原指令0x82c44c、0x82c6a0证实，与客户端发行号1.6.1及更新器版本17170433分开。初次用默认0引发用户截图中的版本错误，已修正服务端，保持原客户端版本校验。
