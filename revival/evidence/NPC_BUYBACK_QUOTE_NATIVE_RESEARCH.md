## ConfigManager+b28 与字段来源

原 getter `89e210` 返回 ConfigManager+b28。ConfigManager 析构 `c983be..c983c9` 对同一成员调用 `884250`，该函数写 vtable `225c2bc`；其 RTTI 直接是 `knight_gsp_npc_Citemsell_table_implement@XMLCONFIG`。原 wrapper `8842d0` 将 lookup 转发到其后台表。这些是同一成员、同一 vtable 的直接证据。

原 `config.pfs/autoconfig/knight.gsp.npc.citemsell.xml` 长 19831 字节，CRC32 `8f8661dc`，SHA256 `403e46a1a75d0b0a2dc0b34438b5314099a4a9fbcd7f6c483533c08cbd91a401`。完整 434 行 attributes/lists 与缓存一致，全部为无子节点的配置行。本批明确遍历全表确认 **40200、40204 缺失，32000 存在**，不把三个查询一律适配为 missing。

32000 原行如下：`id32000, buyprice150, sellprice75, moneytype2, sellnpc10011, ifshow0`。本批运行完整原生成 reader `8840a0..884226`，只有临时 UTF16 字符串和 XML 整数读取作为主机依赖适配；实际字段写入由原指令完成：

| 字段 | 原 record 偏移 | 原写入地址 |
|---|---:|---|
| id | +0 | `8840fa` |
| buyprice | +4 | `88412f` |
| sellprice | +8 | `884165` |

| sellnpc | +10 | `8841d1` |

原 `1103525` 从 ItemRef wrapper+4 取模板 key，原 getter/wrapper 发起查表。若记录 id 不为 -1，`1103537..1103540` 以 **record+4 的 buyprice** 乘 Object+28 的数量，覆盖默认报价。此短分支没有读取 sellprice、moneytype、sellnpc 或 ifshow；不能据此推导 NPC/币种资格。

后台 config cache lookup 在本批是明确的依赖适配：按全部 CRC 已核的 PFS 成员关系，返回完整原 reader 生成的 32000 record，或者真实缺失的 -1 sentinel。原 `89e210` getter、`8842d0` wrapper、真实模板参数、缺失判断、buyprice 读取和乘法均执行；没有替换为“预先算好的报价 getter”，没有运行整个配置缓存加载器。

全表 buyprice 分布是 434 正值、0 零值、0 负值；这只是原数据分布，不建立免费或负价资格规则。

## 默认常量、数量和最终转换

原 `2290090` 的八字节为 little-endian `9a9999999999f13f`，是 binary64 `0x1.199999999999ap+0`，精确值 `2476979795053773/2251799813685248`，比有理数 11/10 大 `1/11258999068426240`。

默认段 `1103506..1103517` 依次执行：`fild` 载入 signed32 价格 map 值，`fmul` 乘该 binary64 常量，`fimul` 乘实际实例 quantity，最后调用原 `19191e0` 转整数。不是先对单件 1.1 倍取整再乘数量。

映像中 `29b8ef8=1`，因此真实 frame 的三项验证沿用该值，实际走原 `19191e9`：把 x87 结果存成 binary64，再由 `cvttsd2si` 向零截断到 signed32。未用 Python 浮点替代该指令。离线 FPCW 显式为 `027f`；未测运行中游戏的启动控制字。

另以四组小整数 `(price,quantity)=(1,1),(9,1),(10,1),(3,5)`，分别交叉 FPCW `{027f,037f}` 与 feature flag `{0,1}`，共 16 条原指令转换 fixture。输出分别为 **1、9、11、16**，每种环境均一致；flag0 实际走原 `1919216` 的 fallback helper，flag1 实际走 `19191e9`，路径地址记录在 JSON。这里只覆盖明确的小值，不声称所有整数溢出或异常价格行为等价。
