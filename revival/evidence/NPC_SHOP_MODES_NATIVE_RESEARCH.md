# NPC 商店付款模式与零价货架：原生研究

方法：research。本批仅离线读第一方映像与 CRC 校验后的原 PFS 资源，执行原 x86 购买构造/序列化指令。新增独立研究脚本及证据，没有修改生产源码、共用政策、真实角色库、客户端或发布；没有连接运行服。

## 可采用的精确结论

**购买请求末字段0对应“银两购买”，1对应“绑银购买”。** 这不是可以无条件放开的付款权限：客户端只表达选择，服务器还须分别校验货架/物品适用币种、绑定产物及原子扣款。原 codec 实际范围是0..11，并非仅0/1；同一请求类型还被特殊商店与快捷购买复用。不能把所有 mode 都映射为现金。

原 `CBuyItemFromNpc@npc@gsp@knight` vtable `2279760`，ctor `daf540` 写 type `c232c`；marshal `e516d0`：BE64 NPC key + BE32 item ID + BE32 count + BE32 mode，20字节。原检查 NPC key 非负、item ID非负、count>=1、mode∈[0,11]；本地数量上限99属于服务端政策，并非这条 codec 的约束。

原服务2跳表分支 `1636d38`，正常路径 `1636d47..1636d64` 把当前 NPC 模板 ID、完整实例 key 高/低及 UI mode0 传给 `10ecaf0` / `110a690`。`10ecb3b` 构造 `1108280`，原 RTTI `CNpcSellItemDlg` vtable `2290118`。本地窗口打开本身没有新增一条服务器报价协议；**这不证明本版本不存在别处报价机制**。

原界面绑定和提交闭环：

| 控件 | 原资源文案 | 绑定到对象 | 购买提交分支 |
|---|---|---|---|
| NpcSellItem/sellDialog/1 | 银两购买 | 字符串2290220；11087c4..1108811 → UI+60 | 110693e读取控件byte+530，选中写mode0 |
| NpcSellItem/sellDialog/2 | 绑银购买 | 字符串2290204；1108822..110886f → UI+64 | 110694f读取控件byte+530，选中写mode1 |

文案从原 `artres/ui.pfs:layouts/npcsellitemdlg.layout` 直接读取，PfsArchive 校验长度和 CRC，JSON 同时保存 SHA256。按钮函数 `1106580` 由原指令执行至 `1106975`；其间 ctor `1106882→daf540`、字段搬运和 `1106973` 提交均执行。仅适配选中物品/数量、控件状态、网络经理与捕获发送；未替换付款模式业务分支。测试包括两个合法选择、两者均选（前者优先）、均未选（构造默认0），并保留非零高32位 NPC key。后两个是合成控件状态的边界证据，不宣称真人能操作出该状态。

## 同包的其它用途

原 UI+78 是商店模式，不能与报文最后字段混淆。`1106887` 起 UI模式5强制报文mode4；UI模式7强制mode9；UI模式8强制mode10并可能改选中条目标识。另独立构造点 `110a355..110a3ad` 写mode6、`13dfa25..13dfa6d` 写mode11、`10e520a..10e527f` 通常写mode8（item ec16特例写0）、`10fc9d0..10fca46` 写mode0。本批仅证明这些赋值，不把未知枚举命名成某币种/免费权限。

## 零价与缺价货架

原 `config.pfs` 直接解析并 CRC 校验 `npcsellitem`、`citemattr`、`cnpcconfig`。全表210行；有原 NPC 定义且货架非空的159行，其中65行至少含一个 price<=0 或缺失/非数字价格。全表异常115行与65的统计范围不同，不能混写。完整逐行数据在 JSON，保留原全部属性，不根据物品描述删货架。

| 货架行 | 原物品 | citemattr.price | 第一方补充描述 |
|---|---|---|---|
| 10157 | 32000 馒头 | 150 | npcid2=10157；普通购买正价对照 |
| 10003 仓库管理员 | 63140 九转飞升丸 | 0 | 原描述可在元宝商城其它杂货购买；npcid2=0 |
| 10000 张世杰 | 63634 上古雌黄、63633 上古遗卷 | 0 | 原描述涉及兑换超级藏宝图；npcid2=0 |

这些描述证明物品还参与其它功能，**不证明该货架售价或可免费发放**，也不证明出现于仓库管理员行就是应开放现金商店。`npcsellitem` 是库存条目，原普通商店路径 `110bd17..110bd33` 通过配置 getter 查输入 ID 并复制条目列表；它没有自行给该 NPC 生成一项服务器服务2授权。菜单服务来自服务器原回包，因此“有表行→一律自动增加service2”的当前恢复方式需要另有服务授权依据；本研究没有证明159行全部原本公开可购买。

本批未追出全部零价项的真实价格来源、专用币种、兑换条件或不可买标记，也未证明 `citemattr.price=0` 是动态报价占位。故三种解释（免费/非现金/不可买）均不能统一套用；保留正价普通购买的已证范围，零/缺价条目应标为待恢复，逐类交对应领域补齐，而不是把0作为免费兜底。原/UI控件判断与服务器权限必须分开。
