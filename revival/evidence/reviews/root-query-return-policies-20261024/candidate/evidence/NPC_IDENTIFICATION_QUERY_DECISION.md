# 495鉴定状态查询裁定

规则唯一来源是design/npc-identification-query-v1.json。恢复该查询、注册NPC关联或接共享入口前读取。2026-10-24主策划依客户端原56例、当前资产模型与同款端游官方研究作此裁定；本页不登记另一套参数。

允许临安原10890/p75的495状态查询：原495本地分支会自行发送c04cc，因此服务器以查询包所带完整NPCkey、即时所属地图证明及明确服务绑定准入，不虚构原本不存在的先行CNpcService495请求。NPC10890→495与128数量预算为designed；原放置、codec、模式1状态消费为client_verified。当前背包设计40格，预算覆盖该容量，同时限制恶意向量；未来背包扩大需连同查询预算明确复核。重复key按原有序vector逐次返回同一当前状态，每次均计入128预算，不转字典去重。

查询只返回当前角色真实背包中已知普通详情的identified0/1，在当前租约事务中冻结inventory_revision；原列表顺序保留，空列表同样检查NPC资格。未知旧详情不补0，已穿/仓库/他人/缺失/过期整包拒绝。当前交互、完整地址、实体、位置版本与原状态约束保持；原NPCkey任何一位不符也拒绝。输出编码在事务结束前完成，失败不产生响应，所有表和版本均无写入。实际网络投递仍须当前连接/场景围栏。

正式收费鉴定另立结果政策，不从本查询获得c4276权限。官方2013-08-30原文支持“附加属性在装备鉴定时有几率随机生成”，旧2012NPC≤40级与当前报价分支有年代差异；原真实level映射、概率、币种、绑定仍未知，详见NPC_IDENTIFICATION_SOURCE_RESEARCH。主策划继续按既有授权补全缺式；查询阶段先不收费，避免产生没有真实鉴定结果的付费操作。

完成条件：NPC所属Module的strict startup/frozen rules、当前证明与资产只读公开Interface、原响应消费、空/多/重复/外物/未知/版本/租约/期限/失败无写入均有独立反馈；再交main单写共享接线。此裁定创建时尚无领域绿、registry激活、部署或GUI证据。

方法：research区分当前原指令与跨年代官方玩法；codebase-design把wire保真、地图准入与角色资产读取置于各自Interface；writing-for-agents共置单一政策指针、可执行范围及完成条件。原服随机鉴定公式与商业容量未验证。
