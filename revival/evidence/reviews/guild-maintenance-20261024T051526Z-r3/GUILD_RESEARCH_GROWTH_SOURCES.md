# 帮派生活技能研究成长：来源与补全接缝

调查日期：2026-10-24。对象：本地 1.6.1 端游客户端、网络版本 601。研究范围是帮派持有的研究等级、研究经验和小时维护；人物学习费用、人物帮派修炼经验不是这份状态。本文只记录证据与候选建议，没有修改程序、共用设计配置、存档或运行服务。

本批使用 research：作为主代理委派的研究子任务，追到官方端游原网页与本包资源，把跨年代差异和未知单列。使用 codebase-design：建议将研究成长的 Implementation 收在帮派所有者 Module 内，以当前维护凭据作为小 Interface，隐藏经验结转、幂等和存储；不让调用方根据个人费用表计算帮派经验。已读取 ARCHITECTURE.md 与 DESIGN_AUTHORITY.md。

## 尚未确认，必须显式设计的项

- 初建帮派各研究技能的初始等级、经验和 cap；已有帮派缺档如何授权建立基线。网页和本表均未给出初始 0/1/40 的结论。
- 每档练功房对应研究力，以及研究力变成每小时 XP 的函数。
- 每一级研究升级 XP，阈值按当前级还是目标级索引。
- cap 是否按技能不同、随帮派等级/建筑等级变化，及原 1.6.1 的最高 cap。
- 升级时是否消费阈值、余量是否结转、同一次维护可升多级、达 cap 后余量是否保留。
- 48 倍资金判据所用时点、维护费组成与取整；基本维护是否仍扣完整维护费。
- 切换研究是否保留各技能独立 XP、停研如何表示、追赶历史维护采用当时还是当前设置。

## 可实现的候选建议（均非原式）

以下供主代理依据 DESIGN_AUTHORITY 补全，只有实际写入唯一设计来源后才成为采用规则：

1. Module 持有逐技能 `(level, cap, xp, next_xp)`，选中研究 ID 独立保存。切换只改变选中项，保留各技能已得 XP；这部分为 designed，不靠窗口默认值补历史档。
2. 小 Interface 接收当前帮派所有者的维护结果/唯一小时凭据，核验该小时处于正常维护、选中技能和研究状态版本后推进。研究经验、等级、维护消费和凭据同事务提交；重试只读既有结果。不暴露一个能被普通调用方任意传入“真实经验奖励”的入口。
3. 数值可先做显式、版本化的独立研究表。例如新建测试帮派起始 40 级，练功房 1–5 档小时经验为 `[100, 200, 300, 400, 500]`，升级至 L 需 `100×L` 经验，独立 cap 暂设 155；所有数字、线性式和初始等级全部标 designed。155 仅借包内可学范围选择保守设计目标，不宣称原硬上限；若采用 140 或其他值也必须明确同样性质。已有帮派不自动套新基线。
4. 候选采用消费阈值、余量结转、同小时可连续升级、到 cap 截止且不继续积累；满级 `next_xp=0`。这是可预测的 designed 选择，必须以阈值前一单位、恰等、超阈值、多级、cap、切研、失败回滚、重登与同小时重试验证。
5. 若完整维护系统还没有可核验正常维护结果，允许先实现纯成长计算和帮派事务内的接收/幂等存储，保持实际小时调度未接；禁止用任意计时器绕过资金/建筑/状态所有权。

上述示例数值没有替代现有 baseline，也没有授权本子任务定稿。现有 `guild_training` 仅选研究项、初始未选（ID 0）；本次未改动该现有行为。
