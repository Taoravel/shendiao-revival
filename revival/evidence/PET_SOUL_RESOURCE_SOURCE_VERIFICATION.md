# 元魂来源与人物唯一资源联动补验

本批只新增跨 Module 验证，既有生产文件保持不变；不实现付费穿戴/摘除/融合或背包珠实例格式。既有元魂来源基础与人物宝石政策仍各自按已封签候选使用。

验证 Seam 为同角色当前租约下的公开元魂 CAS、普通 v2 或完整宝石人物来源 hook、原唯一 HP/MP 存档。角色和宠物均来自临时实际 AccountStore/Inventory；人物五维、生命70/100与真气40/100为明确测试基线，未触碰线上角色或隐式迁移。

`verify_pet_soul_resource_sources.py` 分别实际调用普通 `synchronize_inventory_resource_source` 和完整宝石 `synchronize_inventory_source`。初始化已知元魂列表、改变为明确空列表及推进真实库存版本后，两条 hook 均只推进唯一资源来源，生命70、真气40、上限100/100和资源数值版本保持不变，人物最终属性不变。paid 分支不能修复待结算来源，已结算 paid 在 SQL 禁止写入条件下只读通过。

在元魂 CAS 已执行、根资源凭据 INSERT 时触发真实 SQL 异常，两种政策下元魂列表、库存版本和原资源状态全部回滚。成功重开后根来源版本与当前元魂 CAS 结果的库存版本一致。

方法：TDD 的公开 Seam/真实 Adapter/独立字面预期用于集成验证；此处验证已有组合行为，未声称新增生产行为经历缺失实现红灯。codebase-design 的作用是直接复用既有来源 Interface，没有增加第二资源写入者或测试专用代理层。writing-for-agents 明确区分本次已补验的来源 hook 和仍未知的物品/付费/共享分支；code-review 对新增测试和本说明独立执行 Standards/Spec 固定清单审查。工作区不是 Git，不制造提交或 tracker。

未验证：背包元魂四字段与穿戴六字段的完整双向保真、宠物最终属性、真实技能/战斗权限、材料费用、绑定返还、幂等动作控制器、共享接线/加密投递/部署/GUI及容量。本验证不把修改元魂 map 的可信来源 CAS 当作可直接开放的玩法请求。
