# 召唤兽元魂来源与完整列表基础

状态：可选来源候选；全量恢复进行中。此批实现原数据、纯计算、完整元魂档案持久化及原生刷新，尚不是已付穿戴、摘除或融合动作。原始证据与未知项见 `PET_EQUIPMENT_SOURCE_RESEARCH.md`，批次验证与独立审查见 `pet-soul-source-foundation-batch.json`。

## 使用条件与顺序

1. 启动时 `SoulRules.load()` 加载原28条元魂、15行累计经验、15行摘除数量、158宠模板及22魂技 ID；`pet_soul_storage.prepare(db)` 在 Inventory 表准备后统一执行。规则只读，角色路径不读配置、不建表、不连接或提交。
2. 恢复来源时，调用方须提供明确的完整 `SoulProfile`：真实 role_id、pet_id、政策版本、稳定 source_ref、全部已知槽和每颗元魂六项原始字段。`initialize(..., origin='explicit_known_pet_souls')` 仅接受版本0的完整明确来源；明确的空列表可以保存，缺表记录则 `read` 返回 None，不能推成空槽或默认字段0。此批未自动为新宠创建空元魂来源，也未迁移真实角色。
3. 所有读取、初始化及 CAS 都在同角色当前租约事务里，经公开 Inventory 当前快照验证所有权及未释放宠物。`read` 返回冻结 `SoulBasis`，包含完整宠物快照、库存版本、原始元魂来源和基线字节。重复同一初始化只读当前状态，不复原旧槽位，不覆盖后续变更。
4. `replace_profile(db, inventory, rules, before, after)` 只作可信所属领域的完整来源 CAS：同一角色和宠物、同 source_ref、下一版本、完整 before 相等；成功同时推进库存版本。它不检查背包元魂实例、战斗锁、技能权限，不扣38045、不返还物品、不写幂等凭据。以后穿戴/摘除/融合控制器须先完成对应受理和来源验证，并将材料、返还、元魂 map、原生编码、凭据及当前人物唯一资源来源同步放在同一调用方事务。旧 before 不可重复写；paid 动作由所属控制器跳过 CAS，只读当前已知来源。
5. 提交前对已知完整 profile 调用 `full_refresh` 冻结 `0xc0803 SendPetSouls`，提交后由连接所有者投递。原增量 `0xc0807` 仅覆盖已经存在的槽，不能创建/删除槽，因此此批只暴露完整 map 刷新。`decode_remove` 只解 `0xc0805` 的8字节 petkey/slot1..5 意图，不授予操作权限。穿戴入口仍是原 CUseItem；`0xc0804` 是待恢复的材料融合意图，不作为穿戴。

## 数值含义

bean 六个 BE32 的前三项为 item_id、累计经验、魂技 ID，后3项暂保留 raw4/raw5/raw6，完整提供且保留正负。未猜测其业务含义，不给历史档补零。来源计算只接受原28模板和明确的0或原22魂技 ID；独立原生 bean 编码只核对数据结构，不替代来源验证。

原等级从1起，累计经验比较原经验表 row2..15，等于阈值即升级；row1=20保留，但普通升2阈值为60、高级为120。经验不递减，也不因有效等级受限而截断存档。

原有效上限使用模板 kind/uselevel，不使用当前宠等级。已知 kind!=1 或已穿魂技10002时为15；否则 max(1,trunc(uselevel/10))+是否有10001+明确已知flag22。魂技存在只计一次；缺宠模板或未知flag22拒绝，不能照客户端未知配置回退15放行。`effects` 返回每槽实际级、有效级、原attrid/shuzitype及精确 Fraction 数值，保留420个原始正负平值/比例，不擅自合并或套战斗公式。

原重复判断仅比较精确item_id；普通/高级同属性元魂仍为两个 ID，附加同种互斥规则待后续策略。`removal_quote` 返回原38045移魂符与实际经验级/魂种的原表数量，仅是报价；不表示真实扣料、绑定选择或准入规则已恢复。

## 实际方法与验证

TDD 在既有公开纯计算、调用方角色事务、原生编解码 Seam 逐片进行：三个 Module 缺失的真实导入红灯后实现。预期字面值来自独立原码研究和原配置，未用实现公式生成预期。

- `verify_pet_souls`：28个原XP边界、24个模板/魂技/特权上限组合、3个精确重复判断；420项精确有理数、负比例及 raw 字段保留；真实移魂符 ID；未知来源拒绝。
- `verify_pet_soul_protocol`：原PetSoul构造/序列化/新对象反序列化与全部六字段相同，负 raw 保留；空、2槽、满5槽完整 map 原序列化字节一致，新对象解码后逐槽逐字段核对；原c0805往返、截断包拒绝。宿主仅提供原码执行所需的 CRT 内存适配；没有 GUI 观察者或在线客户端。
- `verify_pet_soul_storage`：临时真实数据库、当前角色租约和原 Inventory 宠物；未知不等于空与明确空档保存、重复导入只读且不重置、来源及库存版本两处 SQL 故障、完成编码后调用方异常均全回滚，旧 before/旧租约拒绝，重新打开保留负 raw 和当前槽位。

codebase-design 将已知来源、版本 CAS、原数值计算与原生格式分开，调用方无需复制原表索引或遍历原树；全体可变状态仍归角色所有者。writing-for-agents 把导入、读取、变更、paid 和编码失败的完成条件同接口并置。code-review 对固定清单按 Standards/Spec 独立复核；非 Git 工作目录沿用固定字节清单，不制造提交或 issue。

未验证：背包元魂物品六字段档案与旗标、五槽开放及额外互斥策略、实际穿戴/摘除/融合材料费用和幂等控制器、魂技符学习与融合经验守恒、与已有宠物完整属性/成长/还童/释放及人物资源来源联动、共享接线/发布/加密投递/GUI/战斗/容量。此批不修改共享入口、原封签鉴定和合成文件、真实数据库或当前服务。
