# 普通装备宝石最终属性与唯一资源存档

本批为可选领域候选，未接共享入口、未发布、未做游戏 GUI 验收。全量恢复目标仍在进行。审查结果以 `role-equipment-gems-batch.json` 和对应固定快照报告为准。

## 接入顺序

1. 启动阶段加载 `GemEquipmentRules.load()`，先准备原装备、宝石、评分表，再调用 `role_equipment_gem_storage.prepare(db)`。热路径只使用已冻结规则。
2. 仅对明确完整来源采用新政策 `2026-10-24.role-equipment-gems.1`。现有人物装备基线与六项非宝石基础属性必须同角色、同政策、同来源标识及基线版本。`initialize_extra` 只接受 `explicit_known_ungemmed_extras`；全部六项都已知才可写入。未知不填零，不自动迁移旧人物。此表只存基础属性来源，没有第二份生命或真气。
3. 采用新政策前，集成方须同时路由升级、治疗、修理、战斗、奖励、背包、登录重连、属性刷新等所有消费者。`carrier_rules` 只供现有公开装备基线及资源来源校验使用；旧的普通装备计算器拒绝新政策，不能仅注册该规则后继续调用旧计算器。默认 v1/v2 注册、出生和运行服均未修改。
4. 同一有效角色租约、同一调用方事务内，先保存真实资源 before，再变更装备。`read_totals` 从当前背包和每件穿戴装备的完整宝石来源及已知宝石前评分重新计算。先调用 socket CAS，紧接既有 `equipment_gem_presentation.apply`，完成道具/费用/绑定等本次其他变更后，调用 `settle_equipment` 合并唯一资源存档。任何异常由调用方回滚整个事务。此 Interface 不授权材料、扣费、技能或 NPC 操作。
5. 新的非上限背包变更使用 `synchronize_inventory_source(..., replayed=False)`；其来源转换明确要求最终上限不变。已付命令由所属领域验证凭据后只调用 `read_profile`，或 `synchronize_inventory_source(..., replayed=True)`。重试严格只读当前状态，不补齐待结算来源，不重算旧事件。
6. 提交前通过 `role_equipment_gem_protocol.growth_refresh(current_growth, profile)` 冻结完整 27 字段原生消息；提交成功后交给连接所有者投递。`profile.core` 是现有 `EquipmentRoleSnapshot`，供已知入场字段读取；额外六项仍需原生属性刷新。编码失败必须回滚，禁止先发成功再提交。

## 数值与证据

14 类普通宝石的原始效果 ID 通过原 `cattributedesconfig.numid` 对应人物数值 ID；210 行均纳入规则验证。原装备基础值通过现有普通 v2 计算器取得；计算时的无评分、白色副本仅供基础值计算，实际评分、颜色、耐久、原始属性及宝石存档不改变。宝石独立相加一次。

保留数值 ID 350、360、370、380、1130、1530；五行吸收为原始百分点数值，治疗量为原始平值。380 的原名称与说明存在冲突，按原数值身份保留。完整六项基线允许显式已知负值，传输必须是精确 float32 的 signed32 整数。

原 numid 链接是 `client_verified`；服务器相加方式、耐久零同时停用装备和宝石效果、未实现伤势的刷新、使用现有 equip 原因处理宝石上限变化，均属明确 `designed`。评分仍沿用已登记的本地设计，未声称复原原服评分公式。此 Module 不伪造任务 EquipmentEvent，不实现战斗吸收公式。

## 验证与限制

TDD 在既有纯计算、角色事务、原生编解码 Seam 执行：缺少当前评分校验器、缺少资源 Adapter、缺少原生 Adapter 各有实际红灯，再完成实现。当前评分检查不构造未来版本，允许已到有效版本上界的装备只读。

纯计算覆盖全部 14 类字面实例、实际六件装备基础值、损坏/修复/卸下及未知来源拒绝。临时真实数据库经现有唯一资源 Interface 证明腰带使生命上限 100→148，再镶绿宝石→203，当前生命保持 70、真气 40；显式生命 180 后损坏裁剪为 100，修理恢复上限 203 但生命仍 100；死亡卸下/重穿不复活。三处真实资源 SQL 故障及完成原生编码后的异常回滚全部装备/资源变更。已付读取与重复基础值初始化在拒绝 SQL 写入条件下通过，旧租约拒绝。

27 字段刷新执行原 `0xec3590/0xec36b0/0xec3730` 构造、序列化和反序列化；原普通属性赋值分支实际写入六项字段，宿主只提供属性槽位，观察者 GUI 未执行。原 21 字段逐项保持。部分/重复顺序/布尔/失真数值及截断包拒绝。

codebase-design 把完整计算与存档组合藏在小 Interface 内，复用根资源 CAS 和已有来源校验；writing-for-agents 将新建、变更、已付、编码失败按分支列明。固定快照以 code-review 的 Standards 与 Spec 两轴独立核对。本目录没有 Git/tracker，采用已有固定文件清单与修改前字节作为对照，不制造提交或 issue。

未验证：真实技能账本与合法操作受理、镶嵌/摘除材料费用及幂等控制器、全部共享消费者切换、线上数据库迁移、加密连接投递、真实游戏界面和战斗效果、并发容量。临时库里的纯镶嵌资源测试未扣材料，不能作为已付镶嵌动作已完成的证据。召唤兽元魂后续沿用 `PET_EQUIPMENT_SOURCE_RESEARCH.md`，不能用人物宝石冒充元魂恢复。
