# 血手印与私有梦境接线裁定

2026-10-23，主策划。单一参数分别为design/newbie-bloodmark-v1.json、design/story-instance-v1.json。开始实现血手印、分配1501剧情实例或加载完整地图地址时读本文，并遵循ARCHITECTURE。原表全族与43路线见BLOODMARK_TASK_FAMILY_AUDIT；现有世界Interface及共享缺口见WORLD_STORY_INSTANCE_HANDOFF。两份政策是设计授权，不是现服已实现证明。

来源顺序已经完成客户端→端游官方剧情说明的核对（JIAXING_MAINLINE_NEXT_AUDIT）。原值3/原CCommit、十个确切任务、目标1501原63/79、原零奖励保留。时间绝对单位、原服务端私有实例、精确传送/结算时点未证，分别设计为3000ms/15000ms票据、每角色每原章节独立梦境、调用方原子提交。坐标×16由mask查询支持但仍标inferred/designed，不当原版事实；原缺失颜色和DisPlayNPCID差异保持。

任务Module持有当前有效血手印ticket，角色Owner受理原CCommit，世界Module重新核真实NPC/位置并预留精确目标。菜单发出时间只是保守服务端起点，客户端没有读条开始或取消上报；不能证明实际点击、阅读或本地取消。可观测移动、换菜单、场景/租约变化均撤销。未经票据的同一16字节包不能完成任务；过早提交不消费合法完成机会。

目录Module负责稳定地址身份，地图Owner负责该完整地址的成员/NPC/移动，任务Module负责章节/原任务资格，持久化Adapter用角色调用方事务组合，不引入全服世界锁或阻塞队列。目录幂等键使用原origin.chapter_id，不采用登录epoch、角色ID直接充实例号或客户端传入地址。设计私有ID空间[2^62,2^63)，随机62位加高位、库唯一、最多8次碰撞尝试；同章节重试返回同地址，冲突不替换。配置启动冻结、DDL启动执行，角色事务中不全表读配置。

先做两条实际纵切。世界窗口实现公开目录allocate/load事务Interface：真实当前租约、明确创建来源/章节冻结证明、稳定幂等/碰撞/晚错回滚/异角色隔离；不自行改共享入口。任务窗口实现十节点资格与读条Interface、原提交/期限/位置变更拒绝及零奖励；精确目标证明和任务完成/原后继激活可加入同一外层事务。双方先交真实公开Interface反馈，再由主集成接完整地址路由；现GameRuntime.map仍按模板键，不能把它误当完整地址入口。

正式传送时源当前完整检查点显式采用、目录精确身份、目标handoff、位置/实例绑定、任务/唯一原type40后继和共用凭据同事务。临时失败保持或恢复唯一源；已提交后清源失败按持久决定恢复原目标实例。重登先恢复handoff再读当前完整地址，缺目录/归属拒绝，不静默回公开1501。客户端仍用原模板1501消息，未证实的q64高位不拼实例号。

首次预算设计为每实例1成员、每进程128已加载剧情实例、每投影64个未完成操作pin及64个未完成场景投递，均由story-instance-v1单一参数读取。64与当前地图邮箱预算相符，但不是原服容量或压测结果。满额拒绝新的局部加载/操作而让其它Owner继续；空闲至少60秒且无成员/预留/冻结/排队交接/未确认场景投递才可卸载运行投影。目录和回执保留。首批静态原NPC冷重建可用，动态删除/生成必须先有其持久快照，否则拒绝冷恢复，不能把已删实体复活。预算不是商业容量实测，卸载也不是删除剧情身份。
