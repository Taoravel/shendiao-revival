# 帮派职位、授权与原生接线条件

职位事务的10组检查、22项原函数核验通过。第九批已接原生帮派查询/任命/辞职三种请求及当前名单，详见[GUILD_NATIVE_RUNTIME.md](GUILD_NATIVE_RUNTIME.md)；NPC授权请求、完整明细和GUI仍待接。当前进程加载与部署均未由本窗口验收，全量目标保持active。

## 已实现的Interface

`OrganizationStore.execute(OrganizationCommand)`在现有按组织ID划分的有界所有者内处理appoint、resign、set_authority。新增guild_offices Module封装职位名额、代次、授权与迁移；它复用调用者事务，不开连接、不commit、不持连接/会话/发送流。`guild_office_snapshot`返回冻结的可信读值，原生公开投影仍须验证请求者租约与成员身份。

- 副帮主一名；左右长老各按帮派等级/2取名额。除数来自官方资料，向下取整显式designed，统一放在recovery-baseline.json。
- 帮主可任命，副帮主须持任命授权；族长可任命本族普通成员为巡察使。巡察使与副帮主是独立职位。
- 左右长老均可禁言普通成员，帮主/副帮主/左右长老受保护。巡察使没有禁言或修改宗旨权限。
- 帮主卸任须有入帮满足72小时的副帮主继任；其他职位辞职清空该职与授权，家族职位保持独立。
- 每项职位绑定家族加入帮派的代次、角色加入家族的代次。退出立即失权，退出再加入不会复活旧职。家族所有者仅改变家族成员状态；帮派所有者随后清理旧职位。
- 旧UNIQUE(guild,position)会错误地限制每种长老只能一人。本批启动迁移保留旧表归档，复制一次；副帮主独占索引保留。二次启动不会从归档复活已撤职位。
- 职位、授权、组织revision与幂等receipt同一事务提交；写receipt失败整体回滚。
