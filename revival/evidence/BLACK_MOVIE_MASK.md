# 首次入场电影遮罩：原生静态证据与可证伪条件

2026-10-23。本批仅只读已有客户端映像，没有打开或操作游戏，没有启停客户端/服务器，没有读取当前进程、发包、改内存或角色。后段遵照主任务要求不新增、运行离线执行探针。

## 当前结论

原客户端确有入服intro判别字段触发 `movieblack.tga → 300000 累计 tick 毫秒` 的全屏遮罩；该字段与真实经验余额独立。未收到 CG 时，显式电影移除路径不会自然执行，但场景正常更新仍可使其在累计 300000 毫秒后自动结束。**不能由此认定此次黑屏就是遮罩，更不能把“未启动 CG”解释为必然永久黑屏。**

控制更新的状态已经确证为 `CGameStateManager+4 == 2`；它也控制世界绘制和主角输入分发。不过 `SEnterWorld` 自身先切换到状态 2，再创建遮罩，故“服务端漏发另一个激活协议，所以状态未到 2”没有本证据支持。本批未取得现场状态、遮罩对象或 elapsed 值。

## 第一方来源

唯一代码来源：[native-image.bin](native-image.bin)，映像基址 `0x400000`，SHA256 `2b49e95d27cbbec0d83a049b5495da4365b205d9a913582b1e6688df67468791`。以下均为该映像的虚拟地址。使用现有 [native_inspect.py](../native_inspect.py) 只做反汇编、RTTI 和静态直接调用检索；未执行映像代码。

## 创建和绘制

1. `SEnterWorld::Process 0x8337c0`，`0x83380a..0x83381c` 比较协议对象 `+0x48/+0x4c` 的64位入服intro判别字段；本文旧称“经验值”有误，真实EXP是外层`+0xf8/+0xfc`。判别的有符号条件及来源边界以NEW_CHARACTER_OPENING_RESEARCH为准；不能拿EXP余额设置它。
2. `0x83382b` 写 `[0x2945438]=BL`。这个地址正是全局 `CGameApplication(0x2945060)+0x3d8`，不是另一个独立标记。RTTI 来自该对象 vtable `0x224db3c`。
3. `0x833831` 先调用应用 vtable `+0x50`，实际 `0x82f490`；后述状态切换在此发生。
4. `0x833833..0x833841` 在 BL 非零且 scene 存在时调用 `0x11df870`。
5. `0x11df8a2..0x11df8b2` 移除旧 `scene+0x39c`；新建 `CSceneEffect`（构造 `0x12ba630`，vtable `0x229ef5c`）；宽串 `0x22972e0` 为 `/artres/image/movie/movieblack.tga`。
6. 仅当效果和纹理均非空，`0x11df92b` 设 `effect+8=0x493e0=300000`，`effect+0x10=texture`；重置 elapsed 和 finished，加入 `scene+0x38c` 的效果容器，并写 `scene+0x39c`。
7. `0x11d3770` 对容器中效果调用 vtable `+0x10`；此类实现 `0x12ba8f0` 按 viewport 宽高构造从 `(0,0)` 开始的矩形并绘制纹理。alpha 默认 `1.0`，乘 255。实际纹理加载失败时不会入容器；仅看到路径字符串不能证明当前有遮罩。

遮罩的 draw/tick/stop 函数中没有主角移动调用或输入拦截。它能够遮住画面；“人物真的不能移动”还需要独立的输入/角色位置判据。未发现它将场景状态改离 2。

## 自然超时、显式移除和暂停条件

`0x12ba660` 是真实效果 tick：读取整数 delta 参数，直接累加 `effect+4`；与 `effect+8` 作有符号比较，达到阈值则调用 vtable `+8`（`0x12babd0`），置 `effect+0x15=1`。函数不读取墙钟，也不判断电影是否播放。`0x12babd0 → 0x12ba690` 释放/移除图像；`0x11d2a30` 的容器循环随后看到 finished，析构并移除该效果。

完整更新链是：

`0x828383` 检查 game-state manager 存在 → `0x828390` 传常量 2 → `0x812ed0` 比较 manager+4 → `0x828435` 调 `0x11d5980` → `0x11d59ec` 调 `0x11d2a30` → `0x11d2a8f` 调效果 tick。

`0x11d5980` 到效果更新调用前没有场景加载/电影暂停的条件早退。可直接确证的暂停情形是：外层状态不是 2，场景对象不存在，未再调用该更新链，或者传入 delta 为 0。上层帧循环是否在当前现场继续运行、delta 数值、此前耗时是否被裁剪，都未取得现场证据；不能用 FPS 数字代替累计 tick 时间。持续正 delta 且场景更新链执行时，“没有 CG 导致遮罩永不超时”与原函数矛盾。

显式清除函数 `0x11d3a10` 读取 `scene+0x39c`，非空时经 `0x11d37d0` 从容器移除并清零该字段。原生电影流程的以下路径均在 `CGameApplication+0x3d8` 非零时清标记并调用它：

| 路径 | 检查/清标记 | 调用移除 |
| --- | --- | --- |
| 电影 section 的移除入口 `0x12bc870`（调用者 `0x12b9a19`） | `0x12bc875 / 0x12bc883` | `0x12bc894` 尾跳 |
| 电影清理分支 | `0x12bfd79 / 0x12bfd86` | `0x12bfd9d` 尾跳 |
| 电影结束清理 `0x12c0970` 内 | `0x12c0aa7 / 0x12c0ab4` | `0x12c0ac4` |
| 播放中重组 section 分支 `0x12c2f50` | `0x12c304f / 0x12c305d` | `0x12c306e` |

自然超时的容器清理不写 `scene+0x39c` 或应用 `+0x3d8`；因此只看这两个字段非零，也不能证明纹理仍在绘制。应以效果容器成员、有效纹理、finished 和实际 draw 为准。该静态差异没有被用来主张当前发生了悬空指针故障。

## 状态 2 的身份、写入和相关门控

`0x814ec0` 创建 8 字节对象，构造 `0x1002e70` 写 vtable `0x22875a4` 并设 `+4=0`。RTTI 为 `.?AVCGameStateManager@@`，全局指针 `0x2945540`。

状态 2 的确定写入者为 `0x81b2e0`：`0x81b2e5` 写 `[manager+4]=2`，并销毁/清空选角相关全局对象 `0x2945544`。它是 `CGameApplication` vtable `+0x4c`（槽地址 `0x224db88`）。`0x82f490` 是同一 vtable 的 `+0x50`：入口 `0x82f4b9..0x82f4bc` 调 `+0x4c`。所以正常的 `SEnterWorld 0x833831 → 0x82f490 → 0x81b2e0` 已写 2；创建黑遮罩在这之后。

直接相关门控：

- 世界绘制：`0x826327..0x826334` 要求状态 2；满足后，还需 scene 存在且 application+0x3ed 非零，`0x826344` 才调用 `0x11d5ce0`。该函数尾部 `0x11d5ef0` 画场景效果容器，所以状态也门控遮罩本身这条绘制路径。
- 主角输入分发：`0x832bb7..0x832bd5` 要求状态 2 且 scene/main-character 存在，随后还有应用 `+0x1ec/+0x1ed` 和其他分支条件。普通主角处理目标 `0x1218030` 在 `0x832c89` 调用。这证明 state 条件能挡住这一输入分发分支，不证明目前具体点击被哪项条件阻止。
- 另有 UI 绘制分支 `0x826557` 同样要求状态 2。完整帧渲染并非只受这一个状态控制。

补充复核 `SRoleEnterScene` 对应的 `0x11e21f0` 场景加载路径：其代码中没有直接引用全局 `0x2945540`，已核对的加载完成尾段包含 `0x11e2d0d` 构造/发送 `CAfterEnterWorld(0xc003d)`；未发现此处理函数直接把状态 2 覆盖成其他状态。此结论只覆盖直接访问，不能排除它调用的其他方法、后续事件或异常路径改变状态。`scene+0x32c` 控制另一段 loading UI 绘制（`0x826620`），而已列的 `0x11d5980` 效果 tick 链前没有按该字节跳过的分支。不能从 loading 画面仍存在就断言效果 tick 已暂停。

## 可核对、可证伪的区分

| 候选 | 若成立所需的现场证据 | 反证/限制 |
| --- | --- | --- |
| 仍在 300000 tick-ms 窗口的原生黑遮罩 | 容器中存在 vtable229ef5c 的效果、有效纹理、elapsed 小于 timeout，且 draw 实际执行 | intro判别字段为0、路径加载日志、场景资源成功均不够；无效果成员/无纹理会否定该项 |
| tick 停止导致超时延长 | 相同效果的 elapsed 不增长，且更新链被跳过或 delta 为 0 | elapsed 正常增长达到阈值后应移除；若仍黑，应转查其他绘制条件 |
| 状态门控同时跳过场景更新与输入 | 当前 manager+4 不等于2，并能定位后来改写/未完成初始化 | 正常 SEnterWorld 已写2；且同一路径也不绘制 scene 效果，不能同时武断断言黑色就是该效果画出的 |
| 画面被遮，但角色其实有移动 | 输入处理和坐标变化存在，画面仍黑 | 与“角色没有移动”须分开验证；本批未采样位置变化 |

这些是后续获得授权与现场数据时可采用的判据，本批没有执行这些现场检查。现阶段保留独立的真实EXP账本及intro字段；CG须匹配角色所属门派和持久剧情授权，root100101仅属于古墓路线；本文不声称黑屏已修复。

## 方法、产物与验证范围

沿用 `research` 的第一方溯源，所有结论回到上述映像地址；采用 `diagnosing-bugs` 将候选和反证分开。用户当前禁止现场操作，因此没有建立能对用户本次黑屏稳定变红/变绿的实际复现环；本批停在静态事实和可证伪判据，不进入根因确认与修复。`codebase-design` 的 Interface 要求落实为：后续观测应在“效果是否入容器/是否 tick/是否 draw”和“状态是否切换/输入是否分发”这些原生 seam 各自取证，不给生产协议增加猜测状态。

产物仅本文件。验证是映像反汇编、RTTI、常量和调用槽相互交叉核对；未验证现场对象状态、实际遮罩像素、当前 delta、输入和角色位移，也没有新增执行探针。
