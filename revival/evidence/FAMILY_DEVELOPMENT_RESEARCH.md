# 家族发展、维护与银箱定向研究

2026-10-23；适用研究对象：本地神雕侠侣 1.6.1 端游 / 网络 601。纯只读调查，未启游戏、服务或战斗，未改生产源码/共享配置。本报告不表示玩法已实现或现场验收。

方法：按 research 委派后台研究，以本包原客户端解码资源和官方端游为第一手来源；按 codebase-design 将“已确认输入/状态规则”与待由所属 Module 隐藏的维护 Implementation 分开，未为未知规则扩张 Interface。读过 ARCHITECTURE.md 与 DESIGN_AUTHORITY.md。原文数值只证明字段或提示；服务端执行次序、取整和身份授权未从文字反推为原服事实。

## 结论与版本冲突

- 确认小时维护、正常维护资金门槛、低人气加费，以及资金不足时仅扣基本费且不产药/特产。具体人气变化公式、每批产量、银箱资金增量仍无可靠原式。
- **本包降级提示 id141507 为 500万资金、1000 人气；2012 官网为 500万资金、500 人气。** 按客户端优先采用本包提示，不能继续把官网 500 当成本版本已证实值。“获得”是否表示加法、重置，以及溢出裁剪仍未被代码/原服确认。
- **drugmax/productmax 是原字段，不足以证明每次新增量；levelupnum 是原字段，不足以独立证明当前级或下一级阈值、累计或消费式建设度。**

### 维护与人气

[family.layout](../decoded/ui/layouts/family.layout)：

- 行123、141（药品/特产提示）说明正常维护时生产，当前家族资金须**大于**正常、特产及药品维护费之和的48倍。文本为严格“大于”。
- 行289说明人气每小时变化一次，在线成员越多增加越多；人气不足1000时维护费增加50%。没有在线人数的系数、固定消耗项、最低增量或离线衰减公式。
- 行276说明建设度是升级唯一指标，只通过银箱获得。
- 行219明确在线/总人数/容量是三个不同数字，不能把总人数直接作为在线样本。

## 官方端游核对

[《快速上手-家族》2012-07-04](https://sdxl.wanmei.com/info/newplayer/20to29/20120704/132338.shtml)，本批浏览重新打开。早期 PC 端资料，**没有直接证明精确匹配本地1.6.1**，故 guide_supported：

它支持达到建设标准自动升级、人气初值1000/上限5000及小时变化，产量与家族等级相关。降级条件为人气或资金<1，降一级；页面降级后恢复500人气和500万资金，与本包1000人气冲突。0级解散后清家族/帮派声望、清除特产外组织任务。该页末尾也要求以线上数据为准。

## 定向检索范围和失败结果

网络检索均带游戏名或官方域限定，关键词组合覆盖：家族/正常维护/简易维护/48/人气/每小时/在线人数/产量/药品数量/特产数量/银箱/10万/建设度。结果主要重复2012家族资料；最后一批四项产量/具体数量检索返回空。早期未加域限定时出现影视“家族/人气”等无关页，全部排除。未检得官方可复核的小时人气公式、生产每批数或银箱资金额。一次低效本地搜索误包含部署快照造成输出截断，随后限定 decoded/config、decoded/ui 和指定 XML 重新查证，结论不依赖截断输出。

本地定向读：cfamilymaintainconfig、cfamilymedicalconfig、cfamilyprogress、citemattr、cgroceryeffect、cmessagetip、cnpcserverconfig、cnpcconfig、bookanswerconfig、bookkeyconfig、cmoneybook、mentaltest，以及 family/familyproduct.layout。搜索到的 personal 人气+12已明确剔除。未执行原生服务端逻辑（客户端本身不能证明服务端公式），未宣称全二进制已排除所有可能线索。

## 可交主策划补全的范围与验证要求

| 尚未知 | 可继续实现时须集中标注 designed 的部分 |
|---|---|
| 人气小时增量 | 在线人数采样/在线时长积分、固定消耗、取整、0人时、上限5000、缺失历史样本拒绝或显式恢复策略 |
| 维护模式 | 48倍等号、生产关闭项参与门槛方式、50%用于哪些费项、旧值/新值人气、扣费与降级先后 |
| 产量 | 每种/共享库存、每次增加/补满、上限、关闭时保留还是清空、升级库存调整；不可把 drugmax 直接冒充新增 |
| 银箱资金 | 两模板的明确资金入账值；建设+1和声望+5保留 client_verified 来源 |
| 自动升级 | 下一行levelupnum映射、建设累计/消耗/重置、一次多级、最高级溢出 |
| 降级/解散 | 本包1000人气优先；资金/人气加法或重置，继任选择，跨帮派/角色任务/库存/场景的可恢复清理 |

按 ARCHITECTURE，维护只由 family owner 顺序结算，以持久 family+hour/batch 识别幂等；不在维护时持有角色/帮派所有者锁等待响应。跨角色清声望、删任务/物品、帮派继任和实例清退须有各自身份代次及可恢复交付。组织事务暂存一个维护结果，不能把角色侧尚未兑现的清理当成已完成。

研究产物仅本报告。验证范围为本批读取/对照和官方网页定向检索；生产实现、原生编码、NPC运行接线、部署、真实 GUI、商业并发/分库均未在本任务验证。
